## 1. 项目概述

### 1.1 是什么
一个 DeepSeek Harness（下称 **DSH**）插件，插件内部包名 `Multi_AI_Conversation`，中文显示名 **【多AI对话】**。

在 DSH 左侧全局导航栏新增一个一级入口「多AI对话」，点击后打开插件自己的独立页面。页面内用户可以：
- 配置 **最多 6 个** AI 大模型，每个独立设置 API 地址、密钥（key）、模型名；
- 在 **工作模式** 与 **游戏模式** 之间切换，两种模式各自独立保存配置；
- （工作模式）输入项目目标，让多个 AI **轮流自主交流讨论**、自主迭代完善方案，等待用户下达「开工」指令后继续；全过程用户可随时插话。

### 1.2 两种模式
| 模式 | 本期是否开发 | 用途 |
|---|---|---|
| 工作模式 | 是（阶段 3 起） | 多 AI 轮流讨论并自主迭代项目方案，支持超时跳过与用户插话 |
| 游戏模式 | 否（仅预留底层与规划） | 让 AI 自主玩狼人杀，用户可自定义道具/角色数量与功能 |

### 1.3 本期总目标（范围边界）
- **做**：导航入口 + 独立页面 + 配置框架 + 工作模式完整对话编排 + 多场讨论历史持久化 + 开工后自动生成/更新「最终方案」Markdown 文件 + 深色主题/缩放兼容 + 类型定义与测试。
- **预留不做**：游戏模式仅建数据结构与界面占位，不实现对局逻辑。
- **禁止**：未经用户明确许可，不上传 GitHub（`https://github.com/shuran10086/Multi_AI_Conversation`）。

### 1.4 已确认的关键决策（来自与用户的问答，不可擅自更改）
| 编号 | 决策点 | 结论 |
|---|---|---|
| D1 | API/密钥/模型配置来源 | **插件自己管理**：每个 AI 在插件页面内单独填 API 地址/密钥/模型；与 DSH 自带模型设置互不干扰 |
| D2 | 左侧导航入口名字/图标 | 名字 **「多AI对话」**；图标用**群聊风格**（多个对话气泡/多人）自绘 SVG |
| D3 | AI 调用方式 | **插件自己发 HTTP 请求**，兼容 OpenAI Chat Completions 格式，**支持流式**（SSE 增量输出） |
| D4 | 工作模式「超时」定义 | **按秒数跳过**：某 AI 在设定秒数内没回完就跳过、轮到下一个；**连续跳过达到设定次数**后，本轮讨论暂时不再叫它 |
| D5 | 第一阶段范围 | **只打地基**：导航入口 + 页面骨架 + 配置存储框架 + 深色主题适配（还不能真正对话） |
| D6 | 「开工」前后区别 | **开工前**=AI 们围绕项目目标头脑风暴、把需求/方案聊清楚；**开工后**=按讨论出的方案开始逐步落实产出，仍为轮流发言 |
| D7 | AI 是否分工 | **每个 AI 可各自设人设/角色**（如架构师、挑刺评审、产品经理）；也允许留空用对等默认提示词 |
| D8 | 讨论产出 | **自动生成「最终方案」文件**（Markdown），开工后由 AI 轮流逐步补全并持续更新该文件 |
| D9 | 产出文件位置 | **用户在设置里指定一个固定输出文件夹**，格式 Markdown；未指定时先提示用户设置 |
| D10 | 开工后产出形态 | **轮流逐步补全**：AI 按顺序把最终方案补全，系统持续更新同一份方案文件，讨论继续直到用户满意 |
| D11 | 测试与依赖 | **零第三方依赖**，用 Node 自带 `node:test`；不引入打包器（纯 JS + JSDoc） |
| D12 | 界面语言 | **中英都做**，跟随 DSH 语言设置自动切换（locale 命名空间 `multiAi`） |
| D13 | 默认参数 | 采用**宽松**一档：超时 120 秒、连续跳过 3 次本轮淘汰、不限轮数、每个 AI 看全部历史、流式开；**全部可在设置里自定义** |
| D14 | 刷新/重开保留 | **配置 + 讨论记录都持久化**；支持**多场讨论历史列表**，可回看/继续任意一场 |
| D15 | 手动点名形态 | `turnOrder=manual` 时：讨论区每个 AI 头像常驻，用户随时点谁就让谁发言 |

## 2. 术语表（大白话 + 术语对照）

- **DSH / Harness**：DeepSeek Harness 桌面端程序，本插件运行在它里面。
- **插件 / bundle（捆绑包）**：一个带有 `package.json` 且声明了 `dsh.bundle.patch` 的普通文件夹，装进 DSH 后生效。
- **Host 半 / Client 半**：插件分两部分。**Host 半**跑在后台（Node 环境，能读写文件、发网络请求）；**Client 半**跑在网页界面（浏览器环境，画 UI）。本插件两半都要。
- **Slot（插槽）**：DSH 界面上预留的「位置」。插件把自己的组件「插」进某个 slot 就能显示出来。
- **sidebar.panellist**：左侧导航栏那一列图标的 slot（放导航入口图标）。
- **main（keyed slot）**：中间主面板区域，按「面板 id」切换显示哪一个页面。
- **ctx**：插件拿到的「上下文」对象，上面挂着各种能力（slots、locale、theme、layout、remote 等）。
- **Remote（远程调用）**：Client 半调用 Host 半方法的通道，形如 `ctx.remote.<命名空间>.<方法>()`。
- **主题 token**：DSH 定义的一组颜色变量（`--dsw-alias-*`），插件只能用它们来上色，这样深色/浅色主题会自动跟随。
- **locale（本地化）**：多语言文案系统；界面文字要走它，便于中英切换。
- **流式 / SSE**：模型回答像打字一样一个字一个字蹦出来的传输方式（Server-Sent Events）。
- **OpenAI 格式**：目前绝大多数大模型 API 兼容的统一请求格式（`POST /v1/chat/completions`，body 带 `messages`、`stream` 等字段）。
- **开工指令**：用户在工作模式下，确认讨论可以进入下一步时发出的明确命令（本插件内的业务概念，非 DSH 概念）。

## 3. DSH 插件架构速查（已通过 cordis_inspect 实测，可直接采信）

> 详细原始数据见 `脚本文件/ref/`（从 DSH 安装包 `app.asar` 提取的官方插件开发技能文档与示例源码）。本节是提炼结论。

### 3.1 插件形态（四个文件起步）
一个带 UI 的插件最少需要：
```
package.json          # 清单：名字、版本、exports、dsh 段
cordis.patch.yml      # 把本插件插入 DSH 的加载链（insert 一行）
index.js              # Host 半：export function apply(ctx, config) {}
client.js             # Client 半：window.__ModuleLoader__.load({ id, factory })
```
`package.json` 关键段（实测模板）：
```json
{
  "name": "@local/multi-ai-conversation",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "icon": "./icon.svg",
  "exports": {
    ".": "./index.js",
    "./client": "./client.js",
    "./package.json": "./package.json",
    "./locale/*.json": "./locale/*.json"
  },
  "files": ["locale/*.json", "icon.svg"],
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "immediately": true, "inject": ["@deepseek-ai/dsh-client-ui-sidebar"] }
  }
}
```
`cordis.patch.yml`：
```yaml
- insert:
    - id: multi-ai-conversation
      name: '@local/multi-ai-conversation'
      config: {}
```
显示元数据（标题/描述）放 `locale/en.json`、`locale/zh.json`，字段形如 `{ "meta": { "title": "多AI对话", "description": "……" } }`。

### 3.2 新增左侧导航 + 独立页面（核心机制，实测确认）
DSH **支持**插件直接注册左侧一级导航项，无需破坏现有功能。机制是「两处注册、同一 id 绑定」：

1. 向 `sidebar.panellist`（list slot）注册一个**图标组件**，带 `id`、`order`、`label`。
2. 向 `main`（keyed slot）注册**页面组件**，`key` 用**同一个 id**。
3. 用户点击该图标 → DSH 自动把主面板切到同 id 的页面。

实测官方 `dsh-client-ui-schedule` 的写法（可直接照抄结构）：
```js
const PANEL_ID = 'multi-ai-conversation';
// 页面
ctx.slots.inject('main', () => ctx.slots.register({
  name: 'main', key: PANEL_ID, locale: NS,
  inject: () => ({ /* 传给页面的 props */ }),
}, MultiAiPage));
// 导航图标
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register({
  name: 'sidebar.panellist', id: PANEL_ID, order: 20, locale: NS,
  label: () => t('panel'),
}, MultiAiIcon));
```
主动跳转页面可调用客户端服务：`ctx.layout.selectPanel(PANEL_ID)`。

### 3.3 Client 可用服务（实测，`ctx.<key>`）
- `ctx.slots`：`inject(ownerKey, cb)` / `register(options, Component)`。
- `ctx.layout`：`selectPanel(panelId)`、`toggleSidebar()` 等（导航/几何）。
- `ctx.locale`：`register(ns, locale, dict)`、`bind(ns)` 返回翻译函数 `t`。
- `ctx.theme`：主题快照、字号；上色统一用 token（见 3.5）。
- `ctx.remote.<ns>`：调用 Host 半暴露的 Remote 方法（持久化就靠它，见 3.4）。
- `ctx.sessions` / `ctx.uiWorkspace` / `ctx.workspaces`：会话与工作区（本插件暂不依赖）。

### 3.4 Host 可用服务与持久化（实测）
- Host 半入口：`export function apply(ctx, config) {}`，可选 `export const inject = [...]`、`export const Config`。
- 所有资源注册都放进 `apply` 内，用 `ctx.effect` / `ctx.on` 并返回清理函数。
- 持久化候选：
  - **普通配置（AI 列表、模式参数）**：Host 半维护一个 JSON 文件（放插件数据目录），通过自定义 **Remote 服务**暴露 `load()/save()` 给 Client（仿照 schedule 用 `ctx.remote.*`）。
  - **密钥（敏感）**：优先用 Host 的 `credentials` 服务（`set/resolve/unset`，按 key 存取），**不要**把密钥明文写进会话日志或普通配置文件。阶段 2 落地时按 `cordis_inspect_query Service credentials` 的精确签名实现。
- 可用能力：`ctx.timer`（超时计时）、`ctx.connection.fetch` / Node `fetch`（发 HTTP）、`storage`/`storageDomain`（结构化存储，可选）。

### 3.5 主题 token（实测，仅可用这些；上色只准用它们）
```
--dsw-alias-bg-base          应用底色
--dsw-alias-bg-layer-1       抬起表面（卡片）
--dsw-alias-bg-layer-2       次级嵌套表面
--dsw-alias-bg-overlay       浮层/弹窗底
--dsw-alias-border-l1        主要细边框
--dsw-alias-border-l2        次级较强边框
--dsw-alias-brand-primary    品牌主色（强调/按钮）
--dsw-alias-label-primary    主文字色
--dsw-alias-label-secondary  次要文字色
--dsw-alias-state-error-primary    错误
--dsw-alias-state-idle-primary     未激活
--dsw-alias-state-success-primary  成功
--dsw-alias-state-warn-primary     警告
--dsw-specific-sidebar-fill  侧栏背景
```
深色/浅色由 DSH 切换 token 值，插件只要引用变量即可自动适配；窗口缩放用相对单位（rem/%/flex），不写死像素布局。

### 3.6 硬性约束（违反会炸或不一致，务必遵守）
1. **禁止** `require('@deepseek-ai/dsh-client-ui-*')` 等任何 DSH Client 包当模块用（`dsh.client.inject` 只排激活顺序，不是可 import 的库）。需要的控件自己写、照抄样式、只共享 token。
2. **禁止**用 iframe 嵌 HTML 页（拿不到主题/locale）。页面必须是渲染进 slot 的 React 组件。
3. **禁止**替换应用根节点、往 `document.body` 追加第二个应用、读别的插件 DOM。
4. factory 内保持无副作用；样式/定时器/监听都在 `apply` 里注册并返回清理函数。
5. 可见文字走 `ctx.locale`；颜色走 token；布局兼容深浅色与缩放。
6. 组件抛错会导致该 slot 空白（控制台 `slot entry crashed in '<slot>'`），需做好容错。

### 3.7 安装与验证方式（实测流程）
- 安装：`plugin_manager` 的 `action: install_bundle`，`target` 为插件文件夹**绝对路径**。安装会自己完成装包与选链，**不要**用 shell 复刻这些步骤。
- 看结果：以返回的 `application`（如 `applied`）和 `warnings` 字段为准，不看日志/进程。
- 确认注册：用 `cordis_inspect_query`（client `Slots.listSubTree`）看 `sidebar.panellist`、`main` 是否出现本插件行。
- 视觉验证：在已连接的 Web GUI（http://127.0.0.1:19387）刷新后人工核对深浅色与缩放。
- React 来自浏览器模块表（`require('react')`），**不要**自带 React / CDN。

## 6. 功能规格

### 6.1 工作模式 — 交互流程
1. 用户在页面选「工作模式」，配置好 1~6 个 AI（可各自设人设/角色，D7）。
2. 用户新建一场讨论，输入**项目目标**并发送 → 作为讨论初始上下文；系统据此生成讨论标题。
3. **【开工前｜discussing 阶段，D6】AI 轮流头脑风暴**，把需求/方案聊清楚：
   - `turnOrder=auto` 自动按顺序；`manual` 时每个 AI 头像常驻、用户随时点谁谁发言（D15）。
   - 一个 AI **完整讲完**后，下一个才开始（严格串行）。
   - 每个 AI 都能看到此前所有（或窗口内）其他 AI 的发言。
4. **超时（D4）**：某 AI 开始后，若 `timeoutSeconds` 内没回完 → 中止它本次输出、标记一次跳过（`status='skipped'`）、轮到下一个；某 AI 连续跳过达到 `maxConsecutiveSkips` → 本轮剩余不再叫它（下一轮恢复）。
5. **用户插话**：
   - `afterCurrent`（默认，安全）：用户输入先排队，待**当前 AI 讲完**后作为一条用户消息插入，再继续轮转。
   - `pauseNow`：立即中止所有正在进行的生成，插入用户消息后从下一个 AI 继续。
6. 用户认为需求/方案聊得差不多了，点「**开工**」按钮下达开工指令。
7. **【开工后｜started 阶段，D6/D10】AI 轮流逐步落实产出**：
   - AI 按顺序把「最终方案」逐步补全，系统持续把结果**汇总更新到同一份 Markdown 文件**（`deliverablePath`，位置见 D9/5.4）。
   - 讨论继续进行，直到用户满意（可随时继续插话、暂停、改配置）。
   - 若未设置输出文件夹（`settings.outputDir===null`），开工时先提示用户去设置里指定（用 `ctx.uiWorkspace.pickDirectory()` 选）。
8. 整场讨论（含消息、阶段、产出路径）随时持久化，进入「多场历史列表」，可回看/继续（D14）。

### 6.2 工作模式 — 配置项清单（界面可改）
见 5.2/5.4 字段；界面分区：
- 「AI 列表」区：增/删/启停/编辑每个 AI（名字、baseUrl、key、model、人设 systemPrompt、温度、颜色）。
- 「对话规则」区：轮流方式、超时秒数、连续跳过次数、插话方式、最大轮数、上下文范围、是否流式、停止关键词。
- 「输出设置」区：最终方案输出文件夹（D9）、产出格式（当前固定 md）。

### 6.3 产出文件（最终方案，D8/D9/D10）
- 触发：开工后，随 AI 逐步补全**持续更新**；也提供「立即导出当前方案」按钮。
- 位置：`settings.outputDir` 下，文件名如 `<讨论标题>-<讨论id短码>.md`（避免覆盖）。
- 格式：Markdown；含项目目标、各 AI 关键结论、最终方案正文。
- 写文件由 Host 半完成（原子写）；未设输出文件夹时阻止生成并提示设置。

### 6.4 游戏模式（仅规划，不开发对局）
- 设置界面可增删改：道具（名字+效果）、角色（名字+数量+能力列表）。
- 数据结构见 5.3，保存到 `PluginState.game`。
- 本期仅保证：切到游戏模式能看到占位界面与「暂未开放对局」提示，配置可存可读。

### 6.5 页面信息架构（骨架，阶段 1 即建）
```
[顶部] 标题「多AI对话」 + 模式切换（工作/游戏）
[主体]
  工作模式：
    左栏 = 讨论历史列表（多场，可新建/回看/继续，D14）
    中栏 = 讨论区（消息流 + 输入框 + 开工按钮 + 阶段标识 discussing/started）
    右栏/抽屉 = AI 列表与规则/输出配置
  游戏模式：占位面板 + 配置入口
```
阶段 1 只需静态骨架 + 空讨论区 + 深浅色正确（历史列表/配置区可为占位）。

## 7. 技术方案（每个功能怎么做）

### 7.1 导航与页面（阶段 1）
按 3.2 注册 `sidebar.panellist`（图标 `MultiAiIcon`）+ `main`（页面 `MultiAiPage`），同 id `multi-ai-conversation`。图标为自绘群聊 SVG，用 `currentColor` 跟随选中态。

### 7.2 配置/讨论存储框架（阶段 1 建骨架，阶段 2 接 UI，阶段 4 接讨论持久化）
- Host 半实现存储服务（命名空间 `multiAi`），暴露 Remote：
  - 配置/设置：`getConfig()`、`saveConfig(patch)`
  - 讨论历史：`listDiscussions()`、`getDiscussion(id)`、`saveDiscussion(d)`、`deleteDiscussion(id)`
- 存储落点（见 5.5）：插件数据目录下 `config.json`、`discussions/index.json`、`discussions/<id>.json`，均**原子写**。密钥走 credentials（阶段 2）。
- Client 半通过 `ctx.remote.multiAi.*` 读写；UI 用本地 React state 承载草稿，保存时下发。
- 阶段 1 先用「内存 + 返回默认 config」占位，确保 Client↔Host 通路打通。
- 插件数据目录解析方式在阶段 1 落地前用 `cordis_inspect_query` 确认（候选：`storageDomain` 或基于 profile 目录的插件专属子目录）。

### 7.3 AI 调用（阶段 3）
- Host 半统一发请求（避免浏览器端跨域/密钥暴露）：`POST {baseUrl}/chat/completions`，`Authorization: Bearer <resolved key>`，body `{ model, messages, stream:true, temperature }`。
- `messages` 组装：系统提示（该 AI 的 `systemPrompt` + 讨论阶段说明）+ 项目目标 + 其他 AI 的历史发言（按 `contextSharing`）。
- 流式：Host 读取 SSE/ReadableStream，逐块通过 Remote stream（`@Remote({mode:'stream'})`，仿 schedule/terminal）推给 Client 实时渲染。
- 超时：`ctx.timer` + `AbortController`，到点 abort 当前请求并记跳过。
- 错误/失败：计入跳过次数，界面以 `--dsw-alias-state-error-primary` 提示。

### 7.4 对话编排状态机（阶段 3/4）
- Host 维护每场讨论的运行态：阶段（discussing/started）、当前轮、当前发言者、各 AI 连续跳过计数、插话队列、是否暂停。
- 严格串行：一个发言 settle（完成/超时/出错）后才取下一个发言者。
- 插话按 6.1 两种策略处理队列。
- 「开工」指令把 `phase` 从 `discussing` 切到 `started`，之后每轮产出汇总写入 `deliverablePath`（7.5）。
- 运行态变化即增量落盘到对应 `discussions/<id>.json`，支持刷新/重开恢复（D14）。

### 7.5 最终方案汇总与写文件（阶段 3/4，D8/D10）
- started 阶段，每轮结束后由 Host 把当前方案汇总为 Markdown，原子写到 `settings.outputDir/<标题>-<id短码>.md`。
- 汇总策略：优先沿用上一版方案并按最新发言增量更新；避免每轮全量重写丢信息。
- 未设 `outputDir` 时，Client 引导用户 `ctx.uiWorkspace.pickDirectory()` 选择后再继续。

### 7.6 本地化与主题
- 文案集中 `locale/zh.json`、`locale/en.json`，命名空间 `multiAi`，跟随 DSH 语言自动切换（D12）。
- 组件样式写在 `*.module.css`，颜色只用第 3.5 节 token；类名加插件前缀防冲突。
